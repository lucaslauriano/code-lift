## A ideia central

Com `N` elementos, a resposta nunca passa de `N + 1` — nem o array `[1, 2, …, N]` consegue bloquear
`N + 1`. Logo, qualquer valor fora de `[1 .. N]` é ruído e pode ser descartado na hora.

## A solução ingênua

```ts
let candidate = 1;
while (a.includes(candidate)) candidate++;
return candidate;
```

Correto e `O(N^2)`: cada `includes` varre o array inteiro, e no pior caso (`[1..N]`) você faz `N`
varreduras. Com `N = 100.000` são 5×10^9 comparações — é exatamente o caso de performance `complete`
desta questão.

A variante `[...new Set(a)].sort()` e procurar o primeiro buraco é `O(N log N)` e passa, mas é mais
lenta e mais fácil de errar na borda (o que fazer quando o menor valor positivo não é `1`).

## A solução ótima

Duas passagens lineares, com o valor servindo de índice:

```ts
const n = a.length;
const seen = new Uint8Array(n + 2);

for (const value of a) {
  if (value >= 1 && value <= n) seen[value] = 1;   // fora da faixa: ignora
}

for (let candidate = 1; candidate <= n + 1; candidate++) {
  if (seen[candidate] === 0) return candidate;
}
```

O `n + 2` no tamanho é para que o índice `n + 1` exista. O filtro `value <= n` é o que mantém o
espaço em `O(N)` mesmo com valores até 10^6 na entrada.

**Complexidade:** tempo `O(N)`, espaço `O(N)`.

Existe uma variante em `O(1)` de espaço extra que permuta os valores in-place (cycle sort), colocando
cada `v` na posição `v - 1`. Vale conhecer, mas ela muta a entrada e é bem mais fácil de errar sob
pressão.

## Armadilhas

- **Zero não é positivo.** `[0]` responde `1`.
- **Só negativos.** `[-1, -3]` responde `1`, não `-2` nem `0`.
- **Valores gigantes.** `[1000000]` com `N = 1` responde `1`. Se você alocar um array do tamanho do
  maior valor, gasta 1MB por causa de um único elemento — e com o limite de 10^6 do enunciado isso
  ainda passa, mas é o hábito que quebra na questão seguinte.
- **Duplicatas.** `[1, 1, 1]` tem três elementos e uma posição preenchida. Responde `2`.
- **Começar o candidato em 0.** A resposta mínima é `1`.

## O que o avaliador da Toptal está medindo aqui

O raciocínio do limite superior. Perceber que a resposta está em `[1 .. N+1]` é o que transforma um
problema com valores até 10^6 num problema com espaço `O(N)` — e é o tipo de observação que o
avaliador consegue ver no seu código sem você explicar nada. Quem não faz essa redução ou aloca um
array gigante, ou ordena, ou cai no `includes` quadrático. As três alternativas funcionam; nenhuma
delas tira 100%.
